# Roadmap

Work tracking for `omni`. This is a live document — add to it freely, clean it up as items land or get rethought.

- **Next** — work identified for the next release, grouped under the version it ships in.
- **Backlog** — work we intend to do but haven't pinned to a release.
- **Ideas** — scrappy reminders that aren't fleshed out enough to be backlog items yet.

---

## Next

### v2.0.0

Two independent breaking changes, so they ship together as one major release. Order of work: providers as data first, then the Decisions API, then additional providers on top of the new provider model.

- **Providers as data** — Replace provider modules with provider structs; dialects stay as modules. The design as built is in `context/design.md` (Providers, Dialects → Compat flags, Thinking). **Phase 1 landed 2026-10-16** (provider structs, loader, config by id, single-fetch sources, `filter:`, per-provider `models:`). **Phase 2 landed 2026-10-16** (compat flags, model thinking data, `handle_event/2`, dynamic thinking). **Phase 3 landed 2026-10-21** (docs: provider moduledocs, tiers, `design.md`). **Phase 4 closed 2026-10-21**: the remaining work became verification (landed 2026-10-23; see `design.md`, Verification and testing), the provider items below and two backlog items; the working notes were retired.
- **Decisions API** — First non-text-generation capability: typed questions over a shared input, returning calibrated probabilities. Two wire formats (System One, OpenAI Decisions). Brainstorm in `context/notes/decisions-api.md`; a second, deeper pass is still owed before implementation. Introduces per-capability dialects on a model, which also lays the groundwork for future modalities.
- **xAI provider** — **Landed 2026-10-27**: `Omni.Providers.XAI` over Responses, xAI's preferred API (Chat Completions is legacy) and the only one with encrypted reasoning. `@ai-sdk/xai` mapped in both sources; `models/2` moves llm_db's models, which it describes as Chat Completions, to Responses. No compat flags: `store: false`, `instructions`, `metadata`, `summary: "auto"` and `prompt_cache_retention` are all accepted. `modify_body/4` drops `reasoning` on models with no effort data, which reject any effort (`grok-4.20-0309-reasoning`, verified). Verified on `grok-4.3` (every scenario) and `grok-4.7`.
- **Mistral provider** — **Landed 2026-10-27**: `Omni.Providers.Mistral` over Completions, `@ai-sdk/mistral` mapped in both sources (Zen serves `mistral-large-4` on Completions, so it loads now), the Completions parser taught Mistral's stream shapes, and `thinking_replay_field` reworked into `thinking_replay_format` with `:content_chunks`. Verified on the free tier with `ministral-8b-2512`; thinking and chunk replay only through OpenCode Zen (see Unverified live). PDFs and tool call ids are backlog items.
- **Together provider** — **Landed 2026-10-28**: `Omni.Providers.Together` (id `:togetherai`) over Completions at `https://api.together.ai/v1`, the documented host (llm_db and Vercel still use `api.together.xyz`). `@ai-sdk/togetherai` mapped in both sources. Flags: `max_tokens_field: "max_tokens"`, `thinking_toggle_format: :reasoning_enabled` (`reasoning_effort` takes no `"none"`), `omit: [:cache]` (caching is automatic, with no retention field). The Completions parser reads cached tokens flat on `usage` and the `"eos"` finish reason. `reasoning_effort` is accepted beyond gpt-oss (GLM-5.3, Kimi-K3, DeepSeek V4 Pro), strict `json_schema` works, and `kitchen_sink` passes without reasoning replay on GLM, Kimi and DeepSeek V4 Pro. Fixtures: Qwen3.5 9B text, thinking and tool use. Sweep: Qwen3.5 9B, gpt-oss-120b, DeepSeek V4 Pro, GLM-5.3-Flash and Kimi-K3; `DeepSeek-V4-Flash-0731` is catalogued but unserved ("no deployments configured for routing"), and Qwen3.5 9B never reports a cache read.
- **Thinking replay on Completions providers** — **Landed 2026-10-28**: `thinking_replay_format` gains `:reasoning_content` and `:reasoning`, which send a message's thinking text in that field. The default stays `:none`, OpenAI's own behaviour. Set on Moonshot, Z.ai, Alibaba and Venice (`:reasoning_content`), Groq and Together (`:reasoning`, the field their reasoning arrives in) and OpenCode's Completions key (`:reasoning_content`). OpenCode's `modify_body/4` moves `mistral-*` models' reasoning into a leading thinking chunk, since Zen passes Mistral's wire through and Mistral rejects unknown fields. NearAI is unchanged (thinking omitted, no key). Prior art (pi, ai-sdk, req_llm, LiteLLM) and models.dev's per-model `interleaved` field agree on the fields. Not adopted: pi's replay in the arrival field, since with a flag the receiving API decides the shape (`design.md`, Parse tolerantly, encode by flag), and the switches that keep earlier turns' reasoning (Z.ai `clear_thinking`, Alibaba `preserve_thinking`, Together `chat_template_kwargs`), left to users (`extra_body`, or module code for Z.ai's, which nests in the `thinking` object Omni sets). Provider baselines assert the field from each thinking fixture. `kitchen_sink` passes with the field on Groq gpt-oss-120b, Kimi K3, GLM-5.3-Flash (Z.ai and Together), Qwen3.8 Flash (Alibaba), Venice's Qwen 3.8 Flash and Zen's DeepSeek V4.1 Flash and `mistral-large-4`.
- **Thinking from other models** — Omni sends back whatever thinking is in the context, whichever model produced it; pi drops thinking from any other model. Signed APIs likely reject foreign thinking: Anthropic gets `signature: nil`, and Gemini and Responses expect their own signatures and encrypted items. Field-based Completions providers take another model's text as their own reasoning. `Message` doesn't record its model (`Response` does), so dropping it selectively first needs that recorded somewhere. The opposite gap: DeepSeek V4 in thinking mode reportedly requires `reasoning_content` on every assistant message ("The reasoning_content in the thinking mode must be passed back to the API"; ai-sdk fills `""`, LiteLLM says `" "` is the minimum), so a message without thinking (from another model, a `thinking: false` turn, or stripped history) would fail. The work: verify which main providers reject foreign thinking and which accept it, check what DeepSeek V4 does with an assistant message without thinking (OpenCode Zen's `deepseek-v4.1-flash` is a good place), then decide whether to drop foreign thinking everywhere or per provider or model, and whether to fill DeepSeek's field.
- **Dynamic thinking** — Landed in phase 2 of providers as data as `thinking: true`: the model's dynamic mode where its API has one, otherwise `:medium`.
- **Upgrade guide and changelog** — Before release, turn `context/notes/v2-changes.md` (the running log of every user-facing v2 change) into an "Upgrading to v2" extras page in the docs, and write a concise `CHANGELOG.md` entry covering the broad areas of change, pointing to the guide. Each v2 phase adds to the log as it lands.

## Backlog

- **Warning mechanism** — Some providers silently drop unsupported features (e.g. Ollama skips URL-based image attachments). Need a consistent way to surface these gaps to users — options include Logger warnings, a warnings list on Response, or warning events in the stream. Compat `omit` gives it the message for free ("this provider ignores `:cache`"), as does `thinking: false` on a model that can't switch off.
- **Per-model base URLs** — Some gateways serve part of their lineup from a different base URL than the provider's: ofox serves Claude models at `/anthropic/v1` and Gemini at `/gemini/v1beta` beside its Completions root; also zenmux, neon, freemodel, and Azure, Bedrock and Vertex with templated URLs. Both sources skip these models with a warning. Open question: a `base_url` on the model that overrides the provider's, or provider modules rewriting the request URL case by case. Additive, so not needed for v2.0.
- **Mistral tool call ids** — Mistral rejects tool call ids that aren't 9 characters of a-z, A-Z, 0-9 (`"Tool call id was ... but must be a-z, A-Z, 0-9, with a length of 9"`, mistral-vibe#1075), so a history from another provider (`toolu_...`, `call_...`) fails there. GLM models on Mistral reportedly emit `chatcmpl-tool-...` ids (pi #8387), which may fail on their own next turn; unverified, as the free tier serves no GLM. The fix is a reshape flag that rewrites non-conforming ids to a deterministic 9-character hash on encode (pi does this); prove it with one verify run carrying a foreign id.
- **Mistral PDF input** — Mistral takes PDFs over Chat Completions as `{"type": "document_url", "document_url": "https://..." | "data:application/pdf;base64,..."}` parts (its `file` part takes only an uploaded `file_id`). The catalog lists no PDF input on any Mistral model, so it needs a new `attachment_format` value plus `models/2` adding `:pdf` (as Venice does). Additive, so not needed for v2.0.
- **Dialect switching** — `Model.put_dialect/3`, so a model can be sent over another dialect in its provider's list (OpenRouter serves one model over Completions, Responses or Messages). Also the fix for OpenRouter's `anthropic/*` cache-control shape. Additive, so not needed for v2.0.
- **Together's DeepSeek V4 Pro thinks with `thinking: false`** — Found by the sweep (`no_thinking` fails). The catalog gives `DeepSeek-V4-Pro-0813` a toggle, and Omni sends `reasoning: {enabled: false}` as Together documents for hybrid models (pi and LiteLLM do the same), but it still reasons. Untried: `chat_template_kwargs: {thinking: false}`, which Together's reasoning docs list as an alternative toggle. If that works, it is module code for this model; if nothing does, the catalog's toggle is wrong.
- **Opus 5.5 thinks with `thinking: false`** — Found by the first sweep (`no_thinking` fails). The catalog gives `claude-opus-5-5` efforts but no `toggle`, so Omni sends nothing for `thinking: false` and the model reasons by default. Confirm against the API whether Opus 5.5 can switch off: if it can, fix the model data; if not, skip `no_thinking` for it in the sweep matrix.
- **Merge streamed `reasoning_details`** — Found while recording OpenRouter fixtures. The Completions dialect keeps every streamed `reasoning_details` fragment as its own entry and sends them all back on the next turn: 76 entries for one DeepSeek answer, 8 for Claude Haiku with the signature on the last only. OpenRouter accepts this (the sweep's `kitchen_sink` passes), but merging fragments by `index` (concatenating `text`, keeping `signature`, `id` and encrypted `data`) would shrink the replayed payload to one entry per block. Fixtures in `test/support/fixtures/openrouter/`.
- **Candidate compat flags** — Seen in prior art (Pi, Vercel, LiteLLM, req_llm); each ships only with a built-in provider that needs it (the ship rule in `design.md`).
  - Anthropic Messages (Fireworks' and OpenRouter's Anthropic endpoints, MiniMax): empty thinking signatures allowed; no `cache_control` on tools; no eager tool-input streaming; temperature unsupported; adaptive thinking forced.
  - OpenAI Responses (OpenRouter): no long cache retention; no developer role; `store: true` rejected. xAI needed none of these.
  - Completions: a forced-tool `output_format` (Groq, Fireworks, req_llm's default).
  - A stateful parse hook for reasoning streamed inline as `<think>` tags (req_llm does this for Groq).
- **Unverified live** — Built-in behaviour not yet run against the live API, for lack of account access:
  - NearAI entirely (no key; wire output unchanged since phase 1).
  - Mistral's reasoning models on its own API (`mistral-small-2603`, `mistral-medium-2604`: 429 on the free tier, which serves them nothing) and GLM on Mistral (`zai-glm-5-3`: 403, not in the tier). Thinking chunks and their replay passed through OpenCode Zen's `mistral-large-4`, which passes Mistral's wire through; the sweep runs that model, and only Ministral on Mistral itself.
  - Groq Qwen: the `"default"` effort and `reasoning_format: "parsed"` (paid plans closed to sign-ups).
  - Ollama Cloud string levels on models other than gpt-oss (`glm-5.3`, `kimi-k3`; paid plan). `glm-5.2` reports an off switch the catalog lacks, so off sends nothing there. `deepseek-v4-flash`, `minimax-m3` and `mistral-large-4` report no thinking values at all.
  - Alibaba's budget-only thinking shape (`qwen3-next-80b-a3b-thinking` isn't served on the international endpoint).
  - Accepted as imperfect: Opus 4.5 and 4.6 use budget thinking rather than adaptive since the prefix lists went.

## Ideas

- **OpenRouter models API as a data source** — `https://openrouter.ai/api/v1/models` carries per-model reasoning data (`supported_efforts`, `mandatory`, `default_effort`) and per-endpoint `supported_parameters`, which llm_db drops. Could feed `Model.thinking` for OpenRouter more precisely than models.dev.
- **Reasoning tokens in `Usage`** — Most APIs report how many output tokens went on reasoning (Completions `completion_tokens_details.reasoning_tokens`, passed through by OpenRouter; Gemini `thoughtsTokenCount`; Responses `output_tokens_details.reasoning_tokens`); Anthropic doesn't. Omni drops the count. It's billed as output, so users may want it; it would also let verify tell "thinking was on" from "the model reasoned".
- **Align source filtering** — ModelsDev drops deprecated models; LLMDB keeps deprecated and drops retired. Pick one rule.
- **Audio and video modalities** — models.dev has these columns but they are currently filtered out in `Model.new/1`. Needs investigation into encoding requirements and provider support before adding `:audio` and `:video` to `@supported_modalities[:input]`. The per-capability dialect shape from the Decisions API work opens the door; no current need, so low priority.
